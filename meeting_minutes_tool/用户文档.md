# 会议纪要助手 — 用户文档

**版本：** 1.0.0  
**适用平台：** Windows / Linux (Debian/Ubuntu)

---

## 1. 产品概述

### 1.1 功能简介

会议纪要助手是一款桌面工具，能够自动识别 PDF 格式的会议纪要文件，提取其中的结构化信息，并汇总到 Excel 文件中。支持以下三种会议类型：

| 会议类型 | 提取内容 |
|----------|----------|
| **党委会** | 议定事项、传达学习等内容 |
| **董事会** | 议案、投票结果等内容 |
| **总经办** | 督查落实、研究事项等内容 |

### 1.2 工作流程

```
PDF 文件放入监听目录
       ↓
自动检测新增文件
       ↓
OCR 识别（百度 API）
       ↓
AI 提取结构化数据（DeepSeek API）
       ↓
写入 Excel 汇总表
```

### 1.3 核心特性

- **文件监控** — 自动检测监听目录中的新增/修改/删除的 PDF 文件
- **缓存加速** — 已处理的文件自动缓存，重复运行秒级跳过
- **断点续传** — 意外中断后重新启动，已处理文件不会重复处理
- **自动备份** — Excel 文件每次写入前自动备份，防止数据丢失
- **文件重命名** — 自动统一文件名中的括号格式为 `〔〕`
- **同名替换** — 同名文件替换内容后自动重新处理

## 3. 前置准备

### 3.1 申请百度 OCR API

1. 访问 [百度智能云控制台](https://console.bce.baidu.com/)
2. 搜索"文字识别"，创建应用
3. 选择「通用文字识别」权限
4. 获取 **API Key（AK）** 和 **Secret Key（SK）**

### 3.2 申请 DeepSeek API

1. 访问 [DeepSeek 开放平台](https://platform.deepseek.com/)
2. 注册并登录
3. 创建 API Key
4. **充值说明：** 免费额度有限，处理一份文件约几分钱，建议提前充值

### 3.3 目录结构准备

监听文件夹建议按以下结构组织，软件会根据目录层级自动检测会议类型：

```
监听目录/
├── 2026/                    ← 年份文件夹
│   ├── 党委会/              ← 会议类型文件夹
│   │   ├── 党委会〔2026〕1号.pdf
│   │   └── 党委会〔2026〕2号.pdf
│   ├── 董事会/
│   │   └── 董事会〔2026〕1号.pdf
│   └── 总经办/
│       └── 总经办〔2026〕1号.pdf
├── 2025/
│   └── ...
├── scan_record.json         ← 自动生成，勿手动修改
└── _cache/                  ← 自动生成，缓存文件
```

**会议类型检测规则：** 软件根据文件路径中是否包含"党委"、"董事"、"总经办"/"总经理"等关键词自动判断。如果不按此目录结构组织，请在文件名中包含上述关键词。

## 6. 详细功能

### 6.1 文件监控

| 事件 | 行为 |
|------|------|
| 新增 PDF | 自动识别、处理并写入 Excel |
| 修改 PDF（同名替换） | 检测 mtime 变化 → 校验 MD5 → 内容变化则先删旧记录再重新处理 |
| 删除 PDF | 自动删除 Excel 中对应行和缓存文件 |

### 6.2 文件重命名

文件名中的括号会自动统一为 `〔〕` 格式：

| 原始括号 | 转换后 |
|----------|--------|
| `【2026】4号` | `〔2026〕4号` |
| `[2026] 4号` | `〔2026〕4号` |
| `（2026）4号` | `〔2026〕4号` |

### 6.3 Excel 备份与恢复

- **每次写入前**自动备份到 `_excel_backup/` 目录
- **文件误删后**下次启动自动从最近备份恢复
- 如果备份也没有，尝试从 `_cache/` 目录中的缓存重建

### 6.4 缓存机制

监听目录下的 `_cache/` 目录保存已处理文件的中间结果：

```
_cache/
├── 2026/
│   ├── 党委会/
│   │   ├── 党委会〔2026〕4号.pdf.md5        # 文件指纹
│   │   ├── 党委会〔2026〕4号.pdf.ocr.txt     # OCR 文本缓存
│   │   └── 党委会〔2026〕4号.pdf.result.json # AI 提取结果缓存
```

**优势：** 重复处理同一文件时直接使用缓存，跳过耗时最长的 OCR 和 AI 步骤。

### 6.5 热力图视图（📊）

- 以 5×10 网格展示 1-50 号纪要的分布情况
- 不同颜色代表不同会议类型（蓝/橙/绿）
- 点击方块可直接打开对应的 PDF 文件

### 6.6 统计视图（📈）

- 按年份 × 会议类型交叉统计 PDF 文件数量
- 可选择是否统计页数（需要读取 PDF 文件）
- 总计行高亮显示

### 6.7 系统托盘

- 关闭窗口时最小化到系统托盘（需安装 `pystray`）
- 托盘菜单：显示主窗口 / 退出程序

## 8. 常见问题

### Q1: 软件启动后闪退

**原因：** 配置文件损坏或缺少必要字段。  
**解决：** 删除 `config.json` 后重新启动，软件会以默认配置运行。

### Q2: Excel 文件被占用无法写入

**原因：** Excel 文件正在被其他程序打开。  
**机制：** 软件会自动重试 5 次，间隔 2 秒。  
**解决：** 关闭正在打开的 Excel 文件，等待自动重试。

### Q3: 处理速度慢

**影响因素：**
- PDF 页数（每页需 OCR 识别）
- API 响应速度（受网络和服务器负载影响）
- 一般每份文件约 1-3 分钟

**加速方法：** 缓存生效后，重复运行可秒级跳过已处理的文件。

### Q4: 如何重新处理某个文件

**方法：**
1. 删除 `scan_record.json` 和 `_cache/` 目录
2. 重新启动软件
3. 所有文件将被重新处理

### Q5: Excel 文件被误删

**恢复机制：**
1. 重新启动软件
2. 软件自动检查 Excel 是否存在
3. 不存在则从 `_excel_backup/` 恢复最近备份
4. 备份也没有则从 `_cache/` 逐条重建

### Q6: 如何查看处理日志

- 界面右侧日志区域实时显示
- 日志内容包括：文件命名、OCR 进度、AI 提取结果、Excel 写入状态

### Q7: 支持 Linux 吗？

- 支持 Debian/Ubuntu，提供 deb 包安装
- 也支持源码直接运行

### Q8: 文件没有按目录结构组织怎么办？

- 文件名中必须包含"党委"、"董事"、"总经办"或"总经理"等关键词
- 否则软件无法判断会议类型，会跳过该文件

## 9. 隐私与安全声明

### 9.1 数据流向

```
PDF 文件（本地）
    ↓
百度 OCR API（云端） ← 图片数据经第三方服务器
    ↓
DeepSeek API（云端） ← 文字内容经第三方服务器
    ↓
Excel 文件（本地）
```

### 9.2 重要提示

本软件在处理会议纪要文件时，会通过以下途径将数据传输到第三方服务：

1. **百度 OCR API** — PDF 转图片后，图片数据发送到百度服务器进行文字识别
2. **DeepSeek API** — OCR 识别出的文字内容发送到 DeepSeek 服务器进行 AI 提取

**请确保：**
- 您所在单位允许将此类信息发送到外部 API 服务
- 涉及国家秘密、商业秘密或个人隐私的文件，**请勿使用本软件处理**
- 使用前建议咨询本单位信息安全部门

### 9.3 数据保留

- 所有处理结果仅保存在您指定的本地 Excel 文件中
- 临时图片在处理完成后自动删除
- 缓存文件保存在监听目录的 `_cache/` 目录中，可手动删除
- 不会将数据用于任何其他目的

---

## 10. 注意事项

1. **不要手动修改 `scan_record.json`** — 这是软件自动生成的扫描记录，修改可能导致重复处理或遗漏
2. **不要删除 `_excel_backup/` 和 `_cache/` 目录** — 用于数据恢复和加速
3. **建议 PDF 文件名规范命名** — 如 `党委会〔2026〕4号.pdf`，便于纪要编号提取
4. **API 密钥请妥善保管** — `config.json` 中保存了明文密钥，注意不要分享该文件
5. **DeepSeek API 需充值** — 免费额度有限，建议提前充值
6. **文件监控仅监控 PDF 创建事件** — 如果文件在软件启动前已放入目录，需通过全量扫描处理
